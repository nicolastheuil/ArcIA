2. Catalogue et qualification des modèles

Chaque ligne associe un fournisseur connecté, un modèle amont, une cible d'exécution et un repli.

Alias & Icône Cible Fournisseur Modèle cible amont Repli (Fallback) ZDR Test
Routage hybride : Une cible Simple envoie directement la requête à LiteLLM Proxy sans latence d'agent. Une cible Agentic garantit le traitement par Hermes Agent (mémoire d'agent SQLite state.db, autonomie multi-étapes et outillage). L'ensemble est filtré par la double barrière Presidio DLP.
Icônes automatiques des modèles (Open-WebUI) : Le Wizard pousse dynamiquement les icônes officielles dans Open-WebUI lors de l'enregistrement de la configuration :
  • Liseret doré : Modèles locaux souverains (Ollama, vLLM) garantissant zéro fuite hors du réseau interne.
  • Liseret argenté : Modèles cloud protégés avec Zero Data Retention (ZDR) et bouclier DLP fail-closed.
  • aIA classique : Modèles standards par défaut. Avec bouclier DLP, sans garantie ZDR.

Étape 4 · Dépôt d’instance et reprise

Préparez le dépôt privé qui conservera la configuration chiffrée nécessaire à une reconstruction.

Dépôt Git d'instance chiffré (AES-256-GCM)

Configurez un dépôt privé neuf ou existant. Vous pouvez reporter cette étape pour une nouvelle instance ; un dépôt déjà déclaré reste surveillé selon son état de déverrouillage.

À conserver par les administrateurs : le mot de passe maître séparément du dépôt ; les skills, MCP maison, services, code, images et dépendances spécifiques dans le dépôt privé, avec leurs versions et instructions de reconstruction. Le wizard ne pousse que instance-secrets.enc et instance.json.

Le snapshot AES-256-GCM inclut la configuration YAML entière, l’environnement et les fichiers locaux de configuration déclarés, dont les identités de déploiement. Les bases, conversations, volumes persistants, etcd, le cluster et les autorisations IAM externes exigent leurs propres sauvegardes et procédures.

Pour une nouvelle instance, vous pouvez reporter la configuration du dépôt. Un dépôt déjà déclaré reste surveillé pendant la session si le coffre est déverrouillé.

Préparer une reconstruction complète

Centre de pilotage : sauvegarde du YAML entier, des environnements, des secrets déclarés et des fichiers de configuration référencés. Les déclarations Power Users enregistrées par le wizard conservent leur personnalité, leurs identifiants, leur stockage demandé et leur état de suspension pour la réapplication.

Les administrateurs maintiennent dans ce dépôt privé leurs skills, MCP maison, services, code, images et dépendances spécifiques, avec les versions et instructions nécessaires pour les reconstruire. Le wizard ne pousse que instance-secrets.enc et instance.json ; les autres fichiers restent sous votre responsabilité.

Les bases de données, conversations, volumes persistants (PVC), etcd et le cluster ne sont pas sauvegardés par ce snapshot. Conservez leurs sauvegardes et procédures de restauration, ainsi que les démarches de rétablissement des accès externes et droits IAM.

Les changements faits uniquement dans le cluster ou dans une application, ainsi que les Power Users historiques non déclarés dans la configuration, doivent être exportés par les administrateurs. Déclarez les fichiers locaux supplémentaires dans instance_backup.additional_files ; les implémentations et dépendances maison restent à maintenir dans le dépôt privé.

Une reprise prépare les fichiers locaux. Vérifiez ensuite la cible, les dépendances, les accès et les données avant de déclencher explicitement le déploiement.
